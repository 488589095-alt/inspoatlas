## 1. 接手时先做什么

1. 阅读本文件。
2. 阅读 `docs/PRODUCT_EVOLUTION.md`、`docs/PRD.md`、`docs/architecture.md`。

5. 修改完成后保持现有私有 Sites 项目和 D1/R2 绑定，不新建站点、不擅自改为公开访问。

可直接复制给新对话：


## 2. 当前产品定位

InspoAtlas 不是 Stitch/Lovart 的轻量替代品，也不是通用白板或收藏夹。它面向 UI、产品与视觉设计师，把分散的图片、网页和文字参考转成：

- 可查找、可分组、可建立关系的灵感画布；
- 有来源依据的视觉拆解与元素候选；
- 可复用的设计基准、提示词、Tokens 和任务包；
- 可供 AI 编码、批量活动页、品牌延展与未来 Figma Bridge 使用的生产上下文。

当前核心路径：

`采集参考 → 拆解素材 → 整理关系 → 明确设计目标 → 形成设计基准 → 按任务导出`

## 4. 已实现能力

### 工作台与画布

- 画布新建、切换、复制、删除和原位重命名。
- 图片、网页、文字、元素、分析和分组等卡片。
- 卡片缩放、Delete 删除、右键菜单、Shift 多选、框选、对齐、撤销/重做。
- 框选必须完整覆盖卡片或分组。
- 分组位于底层，卡片拖入后随组移动，进出组尽量保持关系。
- 自动保存、版本冲突处理和 IndexedDB 草稿恢复。
- 标题/标签/正文/颜色/分析内容检索，命中后选择并缩放定位。
- 关系显示范围、专注模式、独立右下角缩略图和底部操作坞。

### 采集

- 本地多图片、文件夹、文字和公开 URL 输入。
- WXT MV3 浏览器插件，采集目标画布、标题、URL、可读正文、关键样式和分段全页截图。
- 网页截图和正文在卡片内分别滚动查看。
- 插件采集结果按目标 `boardId` 进入对应画布。

### AI 与模型服务

- OpenAI、Anthropic、Gemini、Qwen、DeepSeek、Kimi、智谱、豆包和 MiniMax 等白名单平台。
- 保存记录可重新验证、切换当前服务和删除。
- 真实素材拆解；没有 Key 时不生成假结果。
- 同一素材重新分析会替换原结果，不新增重复分析卡。
- 分析作为来源卡片内的可折叠下拉区域。
- 视觉分析请求限制输出，并使用 240 秒超时；失败保留旧结果并给出中文原因。
- 设计助手要求先说明设计目标，可分析当前选择或整张画布，并要求引用具体卡片依据。

### 设计复用

- 设计基准工作区与多参考合并方向。
- 四种任务目标：AI 网页/UI 复刻、批量活动页、图片/品牌延展、Figma Bridge。
- 导出结构已从杂乱资产包改为按任务选择的任务包。
- 确认后的元素才允许进入复用和导出链路。

## 5. 仍属于部分实现或未完成

新对话不能把下面内容描述成已完成产品能力：

- 设计基准的冲突处理、证据映射和一致性 QA 仍需继续深化。
- Figma Bridge 尚未达到可发布插件状态，也不直接生成原生 `.fig`。
- 自动搜集灵感尚未上线。推荐流程是“目标 → 搜索候选 → 展示来源 → 用户确认 → 采集”，不能做无来源的自动爬取。
- 公开 URL 的复杂页面抓取、登录态网页和反爬页面仍依赖浏览器插件或后续独立抓取服务。
- 没有实时多人协作、评论、移动端、订阅支付和公开素材社区。
- 当前是私有测试站，不是经过正式 SLA、安全审计和合规流程的公开商业产品。
- AI 质量仍需建立不少于 30 个真实设计案例的固定评测集。
- 500 节点 45 FPS、弱网恢复、分享撤销和跨账号权限需要持续做真实设备/生产环境验证。

## 6. 关键代码入口

- `app/InspoWorkspace.tsx`：工作台交互和主要界面。
- `app/workspace/CardNode.tsx`：画布卡片、网页滚动和内嵌分析。
- `app/workspace/model.ts`：场景、节点和持久化转换。
- `app/workspace-v9.css`：当前最新界面覆盖样式。
- `app/api/analyses/route.ts`：单素材真实分析。
- `app/api/ai-credentials/route.ts`：模型服务保存、验证、切换和删除。
- `app/api/boards/[id]/design-assistant/route.ts`：目标导向的画布设计助手。
- `app/api/clips/route.ts`：浏览器插件采集同步。
- `packages/ai/src/index.ts`：多模型适配、结构化分析、文本对话、加解密。
- `packages/domain/src/index.ts`：领域 Schema 和模型目录。
- `db/schema.ts`：D1 数据表。
- `apps/extension/`：浏览器插件。
- `tests/`：当前回归与结构验收。

## 8. 下一轮推荐优先级

1. 用真实 Kimi/Qwen/OpenAI Key 完成图片与网页拆解冒烟测试，记录延迟、费用和结构成功率。
2. 完善设计助手的卡片引用跳转、对话持久化和“将建议转为设计基准候选”。
3. 完成元素框选调整、裁切、确认和导出实物链路。
4. 将设计基准升级为可编辑规则、冲突确认、来源映射和一致性 QA。
5. 选定合法搜索来源，先做自动搜集灵感的候选预览，不做直接自动入画布。
6. 找 5–10 位目标设计师完成观察式可用性测试，而不是继续只靠作者本人使用。

## 9. 交接原则

- 保留当前定位：专业设计参考与生产约束，而非通用生成画布。
- UI 参考 Figma、Adobe 和 Excalidraw 的成熟交互，但只引入服务核心任务的能力。
- 不保留“点击成功但没有真实数据变化”的入口。
- AI 推荐、整理和自动采集必须先预览、再由用户确认。
- 所有分析、元素、规则和导出结论都应能回到来源卡片。
- 新功能先补最小验收测试，再进入私有站部署。
